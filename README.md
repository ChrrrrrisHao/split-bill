# 📄 專案規格書（Specification）— 這攤誰付？Who Pays?

> 聚餐分帳計算機：輸入每一筆花費與「誰先付的」，自動算出每個人該付多少，並給出最少轉帳次數的還款建議。

## 0. 專案概述（Project Overview）

- **產品定位（Positioning）**：免註冊、免安裝、打開就能用的單頁分帳工具。
- **核心痛點（Problem）**：聚餐時「火鍋阿華付、KTV 小明付、計程車小美付」，有人沒喝酒不想分酒錢、有人吃兩份，最後在 LINE 群組算半天還算錯。
- **目標使用者（Target Users）**：大學生聚餐、社團活動、班遊、畢業旅行的記帳人；以**手機**為主要使用裝置，同時支援電腦。
- **技術限制（Constraints）**：單一 `index.html`，CSS／JavaScript 全部內嵌；**不使用任何外部套件、CDN 或字型**，離線也能開；部署於 GitHub Pages。

## 1. 視覺與風格設定（Visual Style）

### 設計概念（Design Concept）
- **「收據 Receipt」風格**：暖色紙張底、等寬對齊的金額數字、虛線撕線、結算區底部鋸齒撕邊，全部結清時蓋上「已結清」印章——讓分帳像在看一張店家收據。

- **成員頭像輪替色（Avatar Colors，10 色）**：`#E8590C` `#1C7ED6` `#2F9E44` `#AE3EC9` `#F59F00` `#0C8599` `#D6336C` `#5F3DC4` `#66A80F` `#495057`
- **主題切換**：預設跟隨系統 `prefers-color-scheme`，可手動切換並記在 `localStorage`；所有顏色以 CSS 變數（`:root` tokens）定義。

### 文字與排版（Typography）
- **內文與標題**：系統無襯線字體堆疊（`system-ui`, `-apple-system`, `"Segoe UI"`, `"Noto Sans TC"`, `"PingFang TC"`, `"Microsoft JhengHei"`, `sans-serif`）。
- **金額數字**：等寬字體（`ui-monospace`, `"Cascadia Mono"`, `"SF Mono"`, `Consolas`, `monospace`）＋ `font-variant-numeric: tabular-nums`，讓金額像收據一樣上下對齊。
- **字級層級**：帳本標題 `clamp(22px, 4vw, 30px)`／800；卡片標題 17px／700；內文 15px；輔助說明 12–13px。

### 特效與質感（Visual Effects）
- **毛玻璃頂欄（Frosted Top Bar）**：`position: sticky` ＋ `backdrop-filter: blur(10px)` ＋ 半透明背景。
- **收據鋸齒撕邊（Receipt Zigzag Edge）**：結算卡片底部以 `radial-gradient` ＋ `mask` 做出撕紙鋸齒。
- **虛線撕線（Dashed Divider）**：每人收支列之間用 `1px dashed` 分隔。
- **「已結清」印章（PAID Stamp）**：所有轉帳都勾選後，紅色雙框印章以 `@keyframes` 從 `scale(2.2)` 縮放並旋轉 `-12°` 「蓋」下去。
- **Emoji 彩帶（Confetti）**：結清瞬間 🎉💸✨🧾 從畫面頂端落下；使用者開啟「減少動態效果」（`prefers-reduced-motion`）時自動關閉。
- **新增高亮（Flash Highlight）**：新增或更新的支出列背景閃一下主色淡底。
- **微互動（Micro-interactions）**：按鈕按下 `scale(.97)`；輸入框 focus 時主色光暈 `box-shadow: 0 0 0 3px`；收支長條圖寬度 `transition: .4s`；Toast 由下往上滑入。

## 2. 佈局與結構（Layout & Structure — Mobile First）

### 尺寸限制（Sizing）
- 以手機為優先：預設單欄，左右留白 16px，最小支援寬度 320px，**不得出現水平捲動**。
- 斷點 `≥ 900px` 改為左右雙欄 Grid；內容最大寬度 1120px 置中。
- 斷點 `< 520px` 時頂欄按鈕只顯示圖示（保留 `aria-label`）。

### 區塊規劃（Sections）
1. **Top Bar 頂欄**：🧾 Logo 與名稱；右側動作按鈕「✨ 範例／🔗 分享／➕ 新帳本／🌙 主題」。
2. **Ledger Header 帳本標題區**：可直接點擊編輯的大標題；下方 4 張統計卡（總花費、支出筆數、成員人數、人均）。
3. **Members Card ① 成員**：名字輸入框＋新增按鈕；成員以「彩色頭像膠囊」排列，各帶 × 刪除鈕。
4. **Expense Form Card ② 新增支出**：類別＋名稱、金額＋付款人、分攤方式分段控制、分攤對象清單（含即時預覽）、服務費勾選、送出按鈕。編輯模式時卡片外框亮主色。
5. **Expense List 支出紀錄**：卡片列表，每列為「類別圖示｜名稱與說明｜金額｜✏️ 🗑️」，點擊可展開分攤明細。
6. **Settlement Panel ③ 結算（收據風）**：每人收支（中線往左右延伸的長條圖）→ 轉帳建議（進度條＋可勾選清單）→ 複製結算文字；底部鋸齒撕邊；結清時蓋印章。
7. **Overlay Layer 浮層**：Toast 提示（可帶「復原」按鈕）、自製確認對話框（Modal）、彩帶動畫。
8. **Footer 頁尾**：隱私說明「資料只存在你的瀏覽器」。

- **電腦版排列**：左欄 ③④，右欄 ⑤⑥。
- **手機版排列**：② → ③ → ④ → ⑤ → ⑥ 由上到下。

## 3. 功能規格（Functional Requirements）

### F1 成員管理（Members）
- 輸入名字按 Enter 或「新增」加入；最多 20 人，名字 1–12 字。
- 名字不可重複（忽略前後空白與英文大小寫），重複時跳出提示。
- 刪除成員：若仍出現在任何支出中（付款人或分攤者），**禁止刪除**並提示「還有 N 筆相關支出」；可刪除時，刪除後 5 秒內可「復原」。

### F2 新增支出（Expense Form）
- **欄位**：類別（🍽️ 餐點／🍺 飲料酒水／🚕 交通／🏨 住宿／🎤 娛樂／🛒 其他）、項目名稱（1–30 字）、金額（正整數，上限 999,999）、付款人（下拉選單）。
- **分攤方式（三選一）**：
  - **⚖️ 平均分**：勾選參與者，總額平均分。
  - **🍱 依份數**：每人 0–20 份（＋／－ 按鈕），依比例分；例如有人吃兩份就給 2 份。
  - **✍️ 自訂金額**：直接輸入每人金額，加總必須等於總額。
- **服務費**：勾選「加收 10% 服務費」→ 總額 × 1.1（四捨五入到元）後再分配。
- **即時預覽（Live Preview）**：每位分攤者旁即時顯示會分到的金額；自訂模式即時顯示「已分配／還差／超過」，數字正確時轉綠色。
- **快捷鍵**：「全選／清除」按鈕。
- **錯誤處理（Validation）**：欄位未填、金額非正整數、沒有分攤者、自訂金額加總不符 → 紅字錯誤訊息，不送出。

### F3 支出紀錄（Expense List）
- 最新在上；顯示類別圖示、名稱、「誰先付・分攤方式 N 人・含服務費」、總額。
- 點擊展開每人分攤明細。
- **編輯**：資料帶回表單，標題變「編輯支出」、按鈕變「更新支出」；可按「取消編輯」或 `Esc`。
- **刪除**：刪除後 5 秒內可「復原」。

### F4 結算（Settlement）
- **每人收支**：已付、應分攤、淨額（正＝應收、負＝應付、0＝打平），以雙向長條圖呈現。
- **轉帳建議**：「誰 → 誰 多少錢」，筆數 ≤ 人數 − 1。
- **還款追蹤**：每筆轉帳可勾選「已還」，顯示進度條與「已還 x／y」；全部完成觸發印章＋彩帶。
- **複製結算文字**：產生可直接貼到 LINE 群組的純文字（標題、總額、明細、轉帳清單、網址）。

### F5 分享連結（Share Link）
- 把整本帳本以 UTF-8 → Base64URL 編碼進網址 `#d=…` 並自動複製；剪貼簿不可用時改以對話框顯示連結。
- 開啟分享連結時，若本機已有資料，先以對話框詢問是否覆蓋；格式錯誤則提示並忽略。
- 載入後清除網址中的 `#d=…`，避免重新整理時重複匯入。

### F6 存檔與帳本管理（Persistence）
- 所有變更即時存入 `localStorage`，重新整理或關閉再開都不會消失；`localStorage` 不可用時網頁仍可正常操作。
- **新帳本**：需確認；清空後 5 秒內可復原。
- **範例**：一鍵載入示範資料（4 人、4 筆，涵蓋三種分攤方式與服務費）。

### F7 無障礙與體驗（Accessibility & UX）
- 所有圖示按鈕皆有 `aria-label`；Toast 使用 `aria-live` 朗讀；Modal 支援 `Esc` 關閉並還原焦點。
- 每個空狀態都有引導文字（例如「還沒有支出紀錄，在『新增支出』填第一筆吧」）。

## 4. 計算邏輯（Business Logic）

- **單位**：一律以新台幣「元」整數計算，不會出現 0.333 元。
- **平均分除不盡**：零頭由付款人吸收（付款人有參與時）；否則由名單前面的人各多 1 元。
- **依份數／含服務費的自訂金額**：使用**最大餘數法（Largest Remainder Method）**分配，保證每人金額加總等於總額，一元不差。
- **淨額**：每人淨額 ＝ 已付總額 − 應分攤總額；全體加總恆為 0。
- **轉帳演算法（Debt Simplification）**：
  1. **精確配對**：應付金額 ＝ 應收金額 的兩人直接配對，一筆結清。
  2. **貪婪配對**：其餘每次讓「欠最多的人」轉給「應收最多的人」，金額取兩者較小值，重複直到歸零。
  3. 結果筆數 ≤ 人數 − 1。

## 5. 資料結構（Data Model）

```json
{
  "title": "週五火鍋＋KTV",
  "members": [ { "id": "k3f9a1", "name": "小明", "c": 0 } ],
  "expenses": [
    {
      "id": "x8d2b0", "title": "麻辣火鍋", "cat": "food",
      "amount": 2400, "payerId": "k3f9a1",
      "mode": "equal",
      "split": { "k3f9a1": 1 },
      "fee": true, "ts": 1760000000000
    }
  ],
  "paid": { "付款人id>收款人id>金額": true }
}
```

- `mode`：`equal`（平均）／`weight`（份數）／`custom`（自訂）
- `split`：平均分時值為 1、依份數時為份數、自訂時為金額

## 6. 技術規格（Technical Spec）

- **結構**：單一 `index.html`（HTML5 ＋ CSS3 ＋ 原生 JavaScript ES2020），無建置流程。
- **相容性**：Chrome／Edge／Safari／Firefox 最新版，手機與電腦。
- **安全性**：所有使用者輸入顯示前做 HTML 跳脫（防 XSS）；分享連結匯入的資料逐欄驗證型別與範圍，不合法的直接丟棄。
- **部署**：GitHub Pages（`main` 分支、根目錄）。
